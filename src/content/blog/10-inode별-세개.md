# inode?
> (index node)
> 파일 하나에 대한 메타데이터를 저장하는 자료구조이다. 리눅스에서 파일이라고 부르는 것의 실체가 inode라고 할 수 있다.

- inode 자체에는 파일 이름이 없다.
	- 파일 이름은 **디렉토리 엔트리**에 저장된다.
	- inode는 이름과는 완전히 분리되어 존재한다.
- inode는 그 inode가 속한 파일 시스템 내에서만 고유하다.

> [!info] 디렉토리 엔트리(Directory Entry)
> 리눅스에서 "이름"과 "inode 번호"를 짝지어 테이블로 저장한 특수한 종류의 파일이다.
> 각 레코드(엔트리 하나)에는 inode 번호, 엔트리가 차지하는 바이트 수, 파일명 길이, 파일 타입, 파일 이름에 대한 정보가 들어있다.

```
디렉토리 "linktest"의 데이터 블록 (= 테이블)
┌───────────┬──────────┬───────────────┐
│ inode번호  │ 타입      │  이름          │
├───────────┼──────────┼───────────────┤
│ 573467    │ 파일      │ inodetest.txt │
│ 573460    │ 파일      │ hardlink.txt  │
│ 573461    │ 심볼릭링크  │ symlink.txt   │
│ 12345     │ 디렉토리   │ .             │  ← 자기 자신
│ 9876      │ 디렉토리   │ ..            │  ← 부모 디렉토리
└───────────┴──────────┴───────────────┘
```


# inode가 담고 있는 정보들
> 파일 이름이 없는 것에 주의하자.
- 파일 타입
	- 일반파일/디렉토리/심볼릭링크/디바이스파일 등
- 권한
	- rwx, 소유자/그룹 실행 권한 등
- 소유자/그룹
	- 파일 소유 정보(UID, GID)
- 크기
	- 바이트 단위의 파일 크기
- 타임 스탬프
	- **atime(접근)**: 읽기만 해도 갱신된다.
	- **mtime(수정)**: 내용이 바뀌면 갱신된다.
		- `ls -l`의 기본 표시값이다.
	- **ctime(inode 변경)**: 내용 또는 inode 자체(권한, 소유자 등)의 변경 시 갱신된다.
- 링크 카운트
	- 이 inode를 가리키는 이름의 개수
	- [하드링크](/blog/11-하드-링크/)의 개수를 말한다. ([5. 마운트와 바인드](/blog/5-마운트와-바인드/)의 바인드 마운트도 같은 inode를 다른 경로에 노출하는 방식이다.)
- 데이터 블록 포인터
	- 실제 데이터가 저장된 디스크 블록 위치

## 직접 확인해보기
`stat` 명령어를 통해 파일의 inode를 확인할 수 있다.

```bash
user1@abc:~/> stat inodetest

  File: inodetest
  Size: 0         	Blocks: 0          IO Block: 4096   일반 빈 파일
Device: 801h/2049d	Inode: 4627845     Links: 1
Access: (0644/-rw-r--r--)  Uid: (  600/    appm)   Gid: (  200/     dba)
Access: 2026-08-29 22:30:21.287227277 +0900
Modify: 2026-08-29 22:30:21.287227277 +0900
Change: 2026-08-29 22:30:21.287227277 +0900
 Birth: 2026-08-29 22:30:21.287227277 +0900
```

- `File`: 파일명
	- inode 구조 자체에는 파일명이 없다. 명령어가 인자로 받은 값을 함께 출력할 뿐이다.
- `Size`: 파일 사이즈
- `Blocks`: 실제로 할당된 디스크 블록 수(512바이트 고정 단위)
	- 실제 파일 사이즈가 작아도 디스크 내부 단편화가 심할 경우엔 실제 디스크 사용량인 Blocks는 크게 나올 수 있다.
- `IO Block`: 파일 시스템이 권장하는 입출력 단위 크기(한번에 읽고 쓸 때 효율적인 단위)
	- 파일 시스템을 만들 때 정해지는 블록 크기이다.
- `Device`: 이 inode가 속한 **파일시스템(디바이스)의 번호** (Major, Minor 순)
	- 블록 디바이스의 드라이버에 따라 Major 번호는 정해져 있다.
	- Minor는 그 드라이버가 관리하는 디바이스 중 몇 번째 구체적 디바이스인지를 나타낸다.
- `Inode`: 이 파일 고유의 inode 번호 
	- **(Device, Inode) 조합이 있어야 시스템 전체에서 완전히 고유하다고 말할 수 있다.**
	- 하나의 시스템(리눅스 운영체제) 안에는 여러 개의 디바이스 각각에 독립된 파일 시스템이 존재할 수 있고 그 안에서만 inode 번호가 유효하기 때문이다.
	- 이 때문에 **하드링크는 파일 시스템을 넘어갈 수 없다.**
- `Links`: 하드링크 개수
- `Access`: 실행 권한
- `Uid`/`Gid`: 소유자/소유 그룹. `(식별ID / 이름)` 형식.


> [!note] 아하모먼트: 여러 개의 파일 시스템? 그 아래 inode? => 마운트는 독립된 파일 시스템을 연결하는 것이구나!
> 하나의 시스템 아래에는 여러 개의 디바이스가 있다. usb, iso, 디렉토리, hdd, ssd, nfs 등등 하나의 파일 시스템을 담을 수 있다. 이렇게 파일 시스템을 담는 무엇이든 마운트의 대상이 될 수 있다. 마운트는 다른 파일 시스템을 내 파일 시스템처럼 접근할 수 있게 붙이는 개념인 것이다..!!
> - 마운트하더라도 {디바이스 번호, inode 번호} 쌍으로 inode를 구분하므로 식별에는 문제가 없다.
