# 1. 리눅스에서의 권한(파일)

> 리눅스는 모든 파일/디렉토리에 대하여 user(소유자), group(그룹), other(기타) 세 가지 대상에 각각 읽기(r)/쓰기(w)/실행(x) 권한을 부여한다.

### 확인해보면서 이해하기

```bash
$ ls -l --파일 정보 자세히 나열

-rwxr-xr-- 1 ok2 devteam 4096 Aug 26 10:00 test.sh
```

### `-rwxr-xr--` (기호 모드)

- (맨앞) 파일 타입: `-`
  - **일반 파일**(`-`), 디렉토리(`d`)
  - 특수 파일: 링크(`l`), 문자장치(`c`), 블록장치(`b`), 파이프(`p`), 소켓(`s`) 등
  - `ls -l /dev`를 실행하면, 파일 유형이 b 또는 c인 파일들을 볼 수 있다.
- 소유자: `rwx`의 권한을 갖는 ok2
- 그룹권한: `r-x`의 권한을 갖는 devteam
- 기타권한: `r--` (그외 모든 사용자)

> [!info] 문자 디바이스 vs 블록 디바이스
>
> - 문자 디바이스는 1바이트씩 순차적으로 접근하여 버퍼링 없이 전달하는 방식의 장치로, 대표적으로 키보드, 마우스, 시리얼 포트 등이 있다. (`/dev/tty` 등)
> - 블록 디바이스는 블록단위로 묶어서 랜덤 접근이 가능하고 버퍼/캐시를 거쳐 처리하는 방식의 장치로, 대표적으로 하드디스크, SSD, USB 등이 있다. (`/dev/sda` 등)

### 권한을 8진수 숫자로 표현하기(8진수 숫자모드)

```
rwx = 111
--- = 000
```

으로 생각해보면, 쉽게 8진수로 바꿔서 생각해볼 수 있다.

```
[파일타입][소유자][그룹][others]
-        rwx   r-x  r--
		 111   101  100
->		   7     5    4
```

`rwxr-xr--`는 위와 같은 계산으로 754로 표현할 수 있게 된다.

# 2. 파일/디렉토리/특수파일에서의 권한 차이

> 파일, 디렉토리, 특수파일에서의 권한은 각각 의미가 다르다!!!

| 권한 | 파일에서       | 디렉토리에서                         | 특수 파일에서            |
| ---- | -------------- | ------------------------------------ | ------------------------ |
| r    | 파일 내용 읽기 | 디렉토리 내 파일 조회(`ls`)          | read()로 파일 읽기       |
| w    | 파일 내용 수정 | 디렉토리 내 파일 생성/삭제/이름 변경 | write()로 파일 내용 변경 |
| x    | 파일 실행      | 디렉토리 진입(`cd`), 내부 파일 접근  | 권한 의미 없음           |

# 3. 소유권과 관련된 명령어들

### 소유권 변경 `chown`

> 파일과 디렉터리의 사용자 소유권과 그룹 소유권을 변경할 수 있다.

```bash
chown [option] 소유자[또는 :그룹명] 파일명

-- '파일명' 파일의 권한을 소유자(또는 그룹명)으로 바꾼다.
```

- `-R` 옵션으로 디렉터리 내부/하위 디렉토리 파일들까지 전부 소유권 변경 가능
- 예시) `chown -R root ok2dir`: `ok2dir` 디렉토리의 소유자를 root로 바꾼다.

### 그룹 소유권 변경 `chgrp`

- `chown`은 소유자/소유 그룹 모두 변경 가능
- `chgrp`은 소유 그룹만 변경 가능

```bash
chgrp [option] 그룹명 파일명
```

### 접근 허가권 변경 `chmod` (별표 다섯 개)

```bash
chmod [option] 파일명
```

으로 파일의 접근 허가권을 변경할 수 있는데, **기호 모드**를 사용한 권한 변경과 **숫자 모드**를 사용한 권한 변경이 있다.

#### 기호 모드로 허가권 변경

```bash
chmod -R o+w ok2dir
```

기호는 `o+w`와 같이 사용한다.

| `o`    | `+`    | `w`  |
| ------ | ------ | ---- |
| 사용자 | 연산자 | 권한 |

의 의미를 순서대로 갖는다고 볼 수 있다.

- 사용자: 소유자(u), 그룹(g), 기타 사용자(o), 모든 사용자(a = u+g+o)가 있다.
- 연산자: 부여(+), 회수(-), 특정 사용자에게 허가권 지정(=)
- 권한: 읽(r)/쓰(w)기, 실행(x)

예시의 `o+w`는 기타 사용자에게 w(쓰기) 권한을 부여하는 동작이라고 해석할 수 있다.

#### 숫자 모드로 허가권 변경

```bash
chmod -R 666 ok2dir
```

숫자는 `666`과 같이 사용한다.

| 6      | 6         | 6           |
| ------ | --------- | ----------- |
| 소유자 | 소유 그룹 | 기타 사용자 |

의 의미를 순서대로 갖는다.
8진수로 풀어 해석하면

| 6      | 6         | 6           |
| ------ | --------- | ----------- |
| 소유자 | 소유 그룹 | 기타 사용자 |
| 110    | 110       | 110         |
| rw-    | rw-       | rw-         |

즉, 모든 사용자가 `ok2dir` 디렉토리 내부 파일과 하위 디렉토리들에 대하여 읽고 쓰는 것이 가능하다는 의미이다.

### 기본 허가권 지정 `umask`

> 새로 생성되는 파일/디렉토리의 기본 허가권 값을 지정한다.

- 파일 기본권한: 666
- 디렉토리 기본권한: 777

이 기본값을 `umask`를 통해 변경할 수 있다.

근데 단순히 값을 할당하는 개념이 아니라, **기본 권한에서 umask 값을 뺀 값**으로 변경된다.

- 빼기 = 컴퓨터 계산으로는 umask 값에 보수를 취하고 기본권한과 AND 연산을 진행한다.

```bash
$ umask

0002
```

가 결과로 나왔다면, 일반 파일의 권한은 666-002 = 664가 된다. (디렉터리 권한: 777-002 = 775)

- 맨 앞의 0은 특수 권한이 부여되었는지를 의미하므로, 권한 계산에 포함하지 않는다.
- `-S`로 umask 값을 문자로 볼 수도 있다.

# 4. 특수 권한

> 프로세스가 실행되는 동안 해당 프로세스의 root 권한을 임시로 가져오는 기능이다.
> 실행 시 적용할 파일 소유자/파일 그룹을 지정하여 프로세스를 실행하도록 적용된다.

- 특수 권한에는 SetUID, SetGID, Sticky Bit가 있다.
  - SetUID = Set User ID (4)
  - SetGID = Set Group ID (2)
  - Sticky Bit (1)
- 특수 권한도 파일/디렉토리에서의 의미가 다르다.

| 특수권한   | 숫자 | 파일에 적용 시                   | 디렉토리에 적용 시                                                                    | ls 표시                                         |
| ---------- | ---- | -------------------------------- | ------------------------------------------------------------------------------------- | ----------------------------------------------- |
| SetUID     | 4    | 실행 시 **소유자** 권한으로 실행 | 의미 없음(무시)                                                                       | 소유자 x 자리에 `s`(있으면) / `S`(x권한 없으면) |
| SetGID     | 2    | 실행 시 **그룹** 권한으로 실행   | 디렉토리 내 새 파일이 **부모 디렉토리의 그룹**을 상속                                 | 그룹 x 자리에 `s` / `S`                         |
| Sticky Bit | 1    | 리눅스에서 의미 없음(무시)       | 해당 디렉토리 내 파일은 **소유자만 삭제 가능** (다른 사용자는 w권한 있어도 삭제 불가) | other x 자리에 `t`(있으면) / `T`(x권한 없으면)  |

### 특수 권한 존재 이유

- SetUID, SetGID: 프로세스가 사용자보다 높은 수준의 접근을 요구할 때 원활한 기능을 제공할 수 있도록 하기 위함이다.
- Sticky Bit: 공용 디렉터리를 사용할 때 소유자나 root에게만 권한을 주고 다른 사용자들로부터 파일을 보호하기 위한 목적으로 만든 것이다.
  - 특정 디렉토리에 접근하여 파일을 생성할 수 있다.
  - 근데 삭제는 소유자와 관리자만 가능.
  - 주로 `/tmp`가 대표적인 예시.
