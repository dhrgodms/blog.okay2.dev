리눅스의 부팅 과정 흐름은 다음과 같다.
```
전원 ON 
  → BIOS/UEFI (하드웨어 초기화) 
  → 부트로더 (GRUB2) 
  → 커널 로딩 
  → init/systemd 실행 
  → 로그인 화면
```

하나씩 알아보자.


컴퓨터 전원을 켜면, 메인보드에 내장된 펌웨어가 가장 먼저 실행된다.
# 1. BIOS/UEFI - 하드웨어 초기화
>  부팅 전에 하드웨어를 점검한다.

## BIOS
- 과거에 계속 사용하던 방식이다.
	- 현재는 레거시 BIOS 모드 형태로 UEFI 안에 흡수됨(신규 하드웨어는 사실상 거의 다 UEFI)
- POST(Power-On Self Test)로 **하드웨어**를 점검한다.
#### Power-On Self Test (POST)
- 하드웨어가 정상 동작하는지 점검하는 진단 과정을 말한다.
- 부트 로더를 실행하기 직전에 BIOS가 수행한다.
- 점검 항목들
	- CPU 인식 여부
	- 메모리 Read/Write 테스트
	- 그래픽 카드 화면 출력 여부
	- 키보드 연결 여부
	- 디스크 인식 여부
- 점검 결과 표현
	- 정상: 조용하게 다음단계로 (또는 짧은 삑 소리)
		- 부트 디바이스를 찾아 부트로더를 실행한다.
	- 문제가 있는 경우: 에러 메시지 또는 비프음(삑삑삑) 또는 부팅 중단

## UEFI
- BIOS보다 기능이 확장된 펌웨어
- GPT 파티션의 ESP라는 특별한 파티션에서 부트로더(`.efi`)를 직접 찾아 실행한다.
	- GPT 파티션은 [2. 파티셔닝](/blog/2-파티셔닝/) 참고
- 부팅 속도가 빠르고, 보안 기능도 지원한다.
- 현재는 거의 부팅 전 하드웨어 점검을 위해 UEFI를 사용한다.

# 2. 부트로더 (GRUB2)
> 커널을 메모리에 올리고, 실행 권한을 넘긴다.

- GRUB2는 요즘 리눅스 배포판 대부분의 기본 부트로더이다.
	- 부트 로더의 세대 교체
	`LILO -> GRUB Legacy (GRUB 1) -> GRUB2`
### 부트로더의 동작 순서
1. 설정파일 읽고 부팅 메뉴 표시
	- 실제 부팅 설정 파일은 `/boot/grub2/grub.cfg`
	- 사용자가 편집하는 설정파일은 `/etc/default/grub`
2. 사용자: 부팅할 커널 선택
	- 부팅 시 여러 OS 중 선택할 수 있다.
	- 바로 이 화면!
	![커널선택화면|333x221](https://www.howtogeek.com/wp-content/uploads/2010/05/sshot169.png)
3. 선택된 커널 이미지(`vmlinuz-*`)와 초기 램디스크(initramfs)를 메모리에 로드한다.
4. 커널에게 제어권을 넘긴다.

---
# 3. 커널 로딩과 initramfs
- 커널(vmlinuz)이 메모리에 올라가고 실제 운영체제 핵심 기능이 시작된다.
- 커널이 루트 파일 시스템에 접근하기 위해 디스크 드라이버가 필요하다.
	- 근데, 이 디스크 드라이브도 루트 파일 시스템 안에 있다면?? => 순환 구조가 되어버린다!
	- 이걸 해결하는게 initramfs

### initramfs
>  부팅에 필요한 최소한의 드라이버와 도구를 담은 임시 파일 시스템을 먼저 메모리에 올려 진짜 루트 파일 시스템을 마운트할 수 있게 도와주는 프로그램이다.

- initramfs를 통해 임시 파일 시스템을 먼저 올린 후, 진짜 루트 파일 시스템을 마운트하여 접근할 수 있게 된다.

---
# 4. init 프로세스 실행 (PID 1)
- init: 커널이 최초로 실행하는 사용자 영역 프로세스
- 요즘 배포판은 대부분 systemd를 사용한다.

### systemd
- PID 1번으로 실행된다.
	- 모든 프로세스의 부모가 된다.
- unit 단위로 서비스, 마운트, 소켓 등을 관리한다.
- target이라는 개념으로 예전의 런레벨을 대체한다.

| 예전 런레벨 | systemd target    | 의미            |
| ------ | ----------------- | ------------- |
| 0      | poweroff.target   | 시스템 종료        |
| 1      | rescue.target     | 단일 사용자 모드     |
| 3      | multi-user.target | CLI 다중 사용자 모드 |
| 5      | graphical.target  | GUI 모드        |
| 6      | reboot.target     | 재부팅           |

- systemd에서는 2,3,4번이 사실상 다 같은 다중 사용자 모드로 취급됨. 
	- SysVinit(systemd사용 전)이 리눅스 배포판 별로 런레벨이 조금씩 다르다.


> [!note] 런레벨(Runlevel)
> 리눅스 시스템이 부팅 후 어떤 동작 상태로 실행될지를 나타내는 개념이다. systemd에서는 target이라는 개념으로 바뀌었다. 일종의 실행 모드라고 보면 된다. 0~6으로된 숫자로 구분한다.


## 미니 실습 systemd target 확인

```bash
systemctl get-default
```

- 실행 결과![](../../assets/blog/3.-부팅과정/3.%20부팅과정-1786888866768.png)
- `set-default`: target 변경
- `isolate`: target 전환

---
# 5. 로그인 화면
로그인 매니저(GUI) 또는 터미널 로그인 프롬프트(CLI)가 뜨면서 부팅이 완료된다.
- 이 로그인 화면이 GUI/CLI로 띄워지느냐도 앞선 기본 target에 따라 결정되는 것!
