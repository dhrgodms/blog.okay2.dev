# 1. 파티셔닝?
하나의 디스크를 여러 개의 논리적 영역으로 나누어 사용하는 것을 파티션이라고 한다.

## 목적
- 운영체제와 데이터 영역의 분리
	- 시스템 손상 시 데이터를 보호할 수 있다.
	- 특정 디렉토리에 남은 용량이 없어도 전체 시스템이 멈추지 않게 한다.
- 여러 파일 시스템을 용도별로 다르게 사용할 수 있다.
- 백업, 복구가 편리해진다.

# 2. 방식: MBR vs GPT
## MBR
- Master Boot Record
![MBR|612x344](https://www.ionos.ca/digitalguide/fileadmin/_processed_/3/3/csm_graphical-representation-of-how-a-master-boot-record-is-structured_1b61431d35.webp)

- 디스크의 맨 앞(0번 섹터)에 위치하는 부팅 정보 및 파티션 구조를 담는 영역이다.
- 512bytes = 부팅 정보 + 파티션 테이블
	- 부트코드: 운영체제 실행을 위한 기계어 명령어
	- 파티션 테이블: 저장 장치 안의 타이션 구조와 위치 정보
		- 최대 **4개 파티션(Primary 테이블**) 지정 가능
	- 부트 시그니처: 해당 섹터가 정상적인 MBR인지 확인하는 표식

### MBR의 한계
- 파티션을 5개 이상 확장하려 하면, 확장 파티션 안에 논리 파티션을 만들어야 한다.
- 디스크 용량 **최대 2TB**까지만 지원한다.
	- 2TB까지만 인식하고, 나머지 공간은 인식을 못해서 사용 못함

> [!question] 왜 2TB까지 지원할까?
> - 파티션 테이블은 파티션이 몇 번째 섹터부터 시작해서, 몇 개의 섹터를 차지하는지에 대한 정보를 담는 공간
> - MBR은 파티션 시작 위치와 크기를 32비트 숫자로 결정함
>   - 주소를 표현할 수 있는 숫자라 32비트까지가 한계라는 거임
> - 하나의 섹터는 주로 512 바이트
> => 2^32 x 512바이트 = 약 2TB 정도 됨


## GPT
- UEFI 시스템에서 사용
	- UEFI = 통합 확장 펌웨어 인터페이스
	- 컴퓨터를 켤 때 가장 먼저 실행되어 하드웨어를 확인하고 운영체제를 불러오는 BIOS의 차세대 표준 규격
	- BIOS처럼 시스템 부팅할 때 처음으로 실행되는 코드임
- 파티션 개수 제한 사실상 없다. 보통은 128개
- 2TB 이상 지원 可
- 파티션 테이블(**Primary 테이블**) 손상 대비를 위한 **Backup 테이블**을 디스크 끝에도 저장
	- 파티션 테이블을 똑같은 걸 또 저장하는거임
	- MBR은 Primary 테이블만 저장

# 3. 파티션 명명 규칙
- IDE 방식
	- hd + 알파벳(a,b,c, ...)
	- `/dev/hda`, `/dev/hdb`
- SATA/SCSI/USB 방식
	- sd + 알파벳(a,b,c, ...)
	- `/dev/sda`, `/dev/sdb`
- 파티션 번호
	- 숫자로 구분
	- `/dev/sda1`, `/dev/sda2`

- MBR에서는 주파티션/확장파티션이 1~4번, 논리 파티션은 5번부터 시작한다.

# 4. 파티션 관련 명령어

- `fdisk`
	- MBR 방식 파티션 관리
	- 대화형
- `gdisk`
	- GPT 방식 파티션 관리
- `parted`
	- MBR/GPT 모두 지원
	- 스크립트 방식 가능
- `lsblk`, `blkid`
	- 현재 디스크/파티션 상태 확인

# 5. Swap 파티션
- 물리 메모리(RAM)가 부족할 때 디스크 일부를 가상 메모리로 사용하기 위한 공간
- 별도의 타입(swap)으로 지정해둔다.
- 권장 크기는 시스템 RAM에 따라 달라진다.
	- 예전에는 RAM의 2배 권장했으나, 요즘에는 RAM 크기 이하도 충분하다.
